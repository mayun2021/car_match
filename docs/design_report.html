摘要

本设计报告针对全国大学生电子设计竞赛 H 题“车载平衡滚球运动控制系统”，以 MSPM0G3507（备选 MSPM03507）为主控，实现三种比赛模式：模式一四路红外循迹沿黑色环形跑道行驶；模式二由 K230 视觉模块识别摆杆/水管内钢球的横向位置，主控通过 MG996R 舵机改变倾角，驱动钢球移动并稳定到指定目标位置；模式三在同一控制周期内并行运行巡线闭环与滚球闭环，并由 MPU6050 记录车辆启动时的初始姿态角。

系统软件按照“应用层—算法层—驱动层—平台适配层”四层组织：应用层实现按键消抖、模式切换与三种任务的状态机；算法层提供通用 PID 控制器，供巡线与滚球两个闭环复用；驱动层封装电机、红外、舵机、K230 协议解析、MPU6050 和调试输出；平台适配层通过统一的硬件抽象接口（HAL）隔离真实 MSPM0 寄存器操作与桌面仿真环境，使核心控制算法可以在没有硬件的情况下先行验证。目前工程已通过桌面仿真（clang -Wall -Wextra -Wpedantic 全量编译无警告，仿真状态机正确进入完成态）验证了状态机跳转、巡线 PID 收敛、停车线识别与丢线/丢球保护逻辑的正确性；真实硬件的 GPIO/PWM/I2C/UART 底层实现已预留标准接口，尚待现场对接与参数标定，本报告第四章对此给出了完整的测试方案和数据记录模板。

关键词：巡线机器人；PID 控制；差速转向；机器视觉闭环；姿态测量；分层软件架构

一、方案论证

评分对应 · 方案论证 · 满分 3

1.1 系统总体方案

小车以 MSPM0G3507 为核心控制器，感知端包括四路红外循迹传感器（YB-MVX01）、K230 视觉模块（通过 UART 输出钢球坐标）和 MPU6050 六轴姿态传感器；执行端包括 TB6612FNG 驱动的两路 MG310 减速电机（差速转向）和一路 MG996R 舵机（改变摆杆/水管倾角）。整体信息流如图 1 所示：各传感器数据汇入主控，主控依据当前比赛模式运行对应闭环算法，再驱动电机与舵机完成动作，调试串口周期性输出遥测数据供现场调参使用。

1.2 循迹方案论证

循迹环节比较了三种常见方案：

  • 单路光电对管循迹：硬件最简单，但只能给出“压线/不压线”的二值信息，转弯响应差，难以满足环形跑道连续修正的需求。
  • 摄像头视觉循迹（如复用 K230 兼做巡线）：可获得连续、精细的黑线位置，但会与模式二的钢球识别任务抢占同一颗视觉芯片的算力和帧率，且图像处理引入的延迟不利于差速闭环的实时性，硬件与算法复杂度也显著上升。
  • 四路红外反射传感器（本方案采用）：成本低、响应快（GPIO 直接读取，无需图像处理延迟）、抗环境光干扰能力较强，缺点是只有 4 个离散采样点。本方案用 −3、−1、+1、+3 的加权平均把离散信号转换为连续误差量（见 2.1 节），在工程实现复杂度与控制精度之间取得平衡，因此最终采用该方案。

1.3 摆杆滚球控制方案论证

钢球位置闭环比较了两种方案：

  • 惯性传感器（陀螺仪/加速度计）估计摆杆角度并结合动力学模型反推球位：不需要额外的视觉模块，但需要建立较精确的摆杆-钢球动力学模型并做状态估计（如卡尔曼滤波），工程实现和现场调试成本高，且无法直接获得钢球的绝对位置误差。
  • K230 机器视觉直接识别钢球位置（本方案采用）：K230 直接输出钢球相对摆杆中心的横向坐标 x_mm，主控只需用“目标位置 − 当前 x_mm”作为 PID 误差输入，不需要额外的状态估计器，闭环结构与巡线闭环高度一致，便于复用同一套通用 PID 模块。代价是依赖视觉帧率与光照条件，因此本方案在协议层加入了超时判定（200 ms 无有效帧即回中并清空积分），把视觉丢帧的风险控制在可接受范围。

二、理论分析

评分对应 · 理论分析 · 满分 5

2.1 小车循迹控制理论

2.1.1 差速转向运动学

小车采用两轮差速驱动结构：左右轮独立由 TB6612FNG 驱动 MG310 减速电机。设基础速度为 v0，PID 输出修正量为 u，则左、右轮速度指令分别为 vL = v0 + u、vR = v0 − u。当黑线偏向小车右侧（误差为正）时，u 为正，左轮加速、右轮减速，车身向右侧修正回到黑线中心；反之向左修正。该差速合成关系在 src/app/robot_app.c 的 run_line_control() 中实现，并在 motor.c 中经过限幅与斜率限制后转换为 TB6612 的方向电平与 PWM 占空比，避免起步、转向瞬间的机械冲击。

2.1.2 离散红外信号的连续误差建模

四路红外传感器从左到右分别赋权 −3、−1、+1、+3。设第 i 路传感器检测到黑线时取值为 1，否则为 0，记检测到黑线的探头数为 n，加权和为 S，则连续误差量定义为：

error = (S / n) × (1000 / 3)　，其中 error ∈ [−1000, +1000]

该式把 4 个离散采样点映射为连续量，使黑线位置在“略偏”和“大幅偏离”之间有区分度，从而可以送入 PID 控制器做比例—微分修正，而不是简单的开关式转向。当 4 路探头均未检测到黑线时（n = 0），程序保留上一次的误差方向，按较低速度原地/小半径搜索，理论依据是环形跑道的曲率有限，短时丢线后黑线大概率仍在最近一次偏移方向附近。

2.1.3 PID 控制律与抗饱和设计

巡线闭环采用位置式 PID：u(t) = Kp·e(t) + Ki·∫e(t)dt + Kd·de(t)/dt，本工程默认 Ki = 0（见 3.4 节参数表），即以 PD 控制为主，理由是巡线误差在稳态附近不存在明显的静态偏差，引入积分项反而容易在弯道处产生超调和振荡。积分项和输出量分别设置了独立限幅（integral_limit、output_limit），防止长时间大误差导致积分饱和，PID 实现见 src/app/pid.c。

2.2 摆杆系统控制理论

2.2.1 钢球位置的等效动力学模型

钢球在摆杆/水管内的运动可近似为：舵机改变摆杆倾角 θ 后，重力沿摆杆方向的分量 g·sinθ 驱动钢球产生加速度，即钢球位置 x 对时间的二阶导数近似正比于 sinθ（小角度下近似正比于 θ）。这是一个二阶被控对象，直接对“角度→位置”闭环用 PID 控制在工程上是可行的：K230 提供位置观测量 x_mm，PID 根据位置误差直接输出角度增量，不需要显式建立速度状态变量，简化了现场实现和参数整定。

2.2.2 视觉位置闭环 PID

滚球闭环误差定义为 error = target_mm − x_mm，PID 输出经限幅后转换为舵机相对中位的脉宽增量 Δus，最终脉宽 = ROBOT_SERVO_CENTER_US + Δus，同样做最大脉宽差限幅，防止舵机角度超出摆杆/水管结构允许的机械范围。相比巡线闭环，滚球闭环保留了较小的积分系数 Ki，用于消除钢球因摩擦、结构轻微倾斜等因素造成的稳态偏差。

2.2.3 视觉丢帧下的安全策略

机器视觉闭环的特有风险是丢帧或误识别。本工程在协议层维护最近一次有效数据的时间戳，超过 200 ms 未更新即判定视觉失效；控制层在视觉失效时立即清空 PID 积分并让舵机回中，而不是保持最后一次输出继续动作。这是因为在无反馈闭环下继续输出等效于开环控制，误差可能持续累积导致钢球或舵机动作发散；清零并回中是工程上更保守、更安全的降级策略。

3.3 状态机与三种模式流程

总状态机维护 IDLE / RUNNING / FINISHED 三种任务状态：空闲态下 MODE 键循环切换模式一/二/三，START 键开始或提前终止任务，CALIB 键在静止状态下重新校准 MPU6050 零偏并让舵机回中；任务运行中检测到停车线、钢球完成 +5 cm/−5 cm 两阶段定位或超时后自动进入 FINISHED 并停止执行器。

模式一：红外循迹（差速闭环）

  • 每 5 ms 读取 PB2–PB5，用 2.1.2 节的方法计算连续误差 error；
  • 误差有效时经 PID 输出差速修正量，按 2.1.1 节合成左右轮速度指令；
  • 误差无效（4 路均未见黑线）时，按最近一次误差方向低速原地/小半径搜索；
  • 起步 1500 ms 内忽略停车线判定，之后 4 路连续 60 ms 全黑视为到达 A 点停车线，任务完成。

模式二：K230 视觉滚球（位置闭环）

  • 解析 K230 发送的 B:x_mm 或 $BALL,x_mm,y_px,valid 两种文本帧；
  • 视觉有效时按 2.2.2 节计算误差并输出舵机脉宽增量，先控制钢球到 +5 cm 并稳定 500 ms，再切换到 −5 cm；
  • 视觉超时（>200 ms 无有效帧）时立即清空积分、舵机回中，避免开环发散（见 2.2.3 节）。

模式三：巡线 + 滚球综合

同一个 5 ms 控制周期内先执行模式一的巡线闭环，再执行模式二闭环（去掉 ±5 cm 序列，目标固定为球在摆杆中心），MPU6050 在任务开始时清零偏航角，仅用于记录车辆运动过程中的相对姿态角，不参与任何闭环反馈。调参时应先分别调通模式一、模式二，再降低车速和舵机限幅进入模式三联调，避免两个闭环互相扰动。

4.4 结果分析

现阶段的桌面仿真结果表明：状态机的模式切换、任务启停、停车线识别、丢线降级等控制流程在逻辑上是正确的，PID 计算路径、协议解析路径均已跑通且没有编译期隐患（-Wall -Wextra -Wpedantic 零警告）。但桌面仿真无法覆盖真实的机械动力学特性（电机死区、舵机响应延迟、钢球与摆杆的摩擦等），因此 3.4 节给出的 PID 参数只是保守的初始值，仍需按 docs/tuning.md 中的现场调参顺序（电机方向 → 巡线 PID → 舵机与滚球 PID → 模式三联调）逐步标定，并将实测结果补充到表 5、表 6 中，作为最终答辩材料的数据支撑。

五、结论与展望

评分对应 · 设计报告结构及规范性 · 满分 3

本设计采用四路红外加权误差 + PID 差速控制实现稳定巡线，采用 K230 视觉位置反馈 + 舵机 PID 实现钢球位置闭环控制，并通过统一硬件抽象层实现了“先仿真、后上板”的分阶段验证路径，目前已在桌面仿真环境下验证了控制算法与状态机逻辑的正确性。

主要工作与创新点：

  • 采用应用层/算法层/驱动层/平台适配层的分层架构，PID 控制器作为独立算法模块被巡线、滚球两个闭环复用，降低了重复实现和调参口径不一致的风险；
  • 引入硬件抽象层（HAL），使核心控制逻辑可以脱离真实硬件在桌面环境下编译并运行仿真测试，提前暴露状态机和协议解析中的逻辑错误；
  • 对丢线、视觉丢帧等异常情况都设计了明确的降级策略（低速搜索、清积分回中），而非简单停车或保持最后输出。

存在的不足与后续计划：

  • 真实硬件的 GPIO/PWM/I2C/UART 驱动尚待对接 TI SysConfig 与 DriverLib，是当前最主要的待完成工作；
  • PID 参数目前为保守初始值，需要在真实机械结构上按 docs/tuning.md 流程重新标定；
  • 模式三双闭环并行时的相互耦合（车身振动对滚球稳定性的影响）需要通过现场联调进一步验证和优化。

附录 B：K230 通信协议

K230 每 20–50 ms 通过 UART 发送一帧 ASCII 文本，支持两种格式，任选其一：

  • 简化协议：B:<x_mm>，例如 B:-14.2 表示钢球在中心左侧 14.2 mm；
  • 兼容协议：$BALL,<x_mm>,<y_px>,<valid>，例如 $BALL,8.0,121,1，valid=0 表示本帧未可靠识别到钢球。

主控超过 200 ms 未收到有效帧即判定视觉超时，进入 2.2.3 节所述的安全降级策略。
